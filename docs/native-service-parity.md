# Native 创建与会中设置接口接入

2026-10-11，按用户授权恢复服务端接入。保持 Web PC/Phone 已确认的布局；Native 继续依赖共享 Phone 设置内容与 i18n，不导入 Web Hook，也不使用浏览器 Cookie 或部署密钥调用旧接口。

## 本批实现

| 范围 | App 行为与服务端来源 |
| --- | --- |
| 创建 / 加入 | 首页手动输入不存在的 Space，先 POST `/api/v1/native/spaces` 创建，再走原 prepare / RTC / confirm；已存在只加入，不覆盖设置或抢占房主。滑动预览仍只加入已有 Space。 |
| 创建策略 | 尊重部署的 `create_space`；匿名 App 可使用 `all` 或显式 `*` 白名单。需要平台身份或指定用户白名单的部署拒绝匿名创建，不能拿昵称伪装可信身份。 |
| 默认 Room | 使用 domain 的 `DEFAULT_SPACE_INFO(..., true)`，保留 Meeting Room 与 ☕️ Coffee Break 两个公共 Room。创建本身不登记参会成员、不打开设备。 |
| 房主身份 | 服务端创建凭据绑定当前 Native 会话；RTC 确认后原子绑定所有权，并允许麦克风/摄像头/屏幕采集，设备仍由用户主动开启。重新入会使用新 RTC identity，迟到的旧退出请求不能移除新连接。 |
| 常规 / 资料 | 状态、名称、提示音读写；名称同步 LiveKit；原 Web Socket 收到数据更新通知。AVO 预设保存、加载、删除写回同一 participant 数据。 |
| 音频 | 音量与降噪/回声消除/自动增益读写，应用到 Native 远端音量与麦克风采集参数；具体设备效果仍需真机验证。 |
| 视频 | 共享音频、虚化与虚拟角色/背景偏好可保存读取。App 目前没有相应媒体效果处理，界面明确提示，保存不会宣称这些效果已生效。 |
| 房间管理 | 房主可修改持久化、访客策略、RBAC、应用开关；成员只能保存自身应用同步权限和偏好。房主关闭访客后仍保留自身访问，其他访客由既有成员校验阻断。 |
| 会中展示数据 | 目录附带公共成员名称、状态、房主标识及当前 AVO 颜色；不返回私密 Room 成员资料、全量个人设置或部署配置。 |
| 录制记录 | 有权限者读取真实 S3 列表、生成 60 秒下载链接；房主/管理员可经确认删除。未配置 S3 显示未配置，有服务错误显示错误，不伪装空数据。只允许本 Space 下的直接 MP4 文件。 |

## 接口与权限

- `POST /api/v1/native/spaces`：严格接收 `{spaceName}`。Lua 原子创建与索引、创建者凭据写入；重复创建返回现有 Space，不重复初始化。所有权不从客户端 identity、昵称、role 获取。
- `POST /api/v1/native/settings`：已确认入会后的设置快照。合并旧成员缺失的默认偏好及音频/虚拟形象子项，返回自身偏好、权限矩阵与服务端计算的房间能力；仍不回传密钥/证书。
- `PUT /api/v1/native/settings`：`{joinId, patch}`；逐字段验证类型、范围、字符串和预设数量；自身字段与房主字段分开授权，不允许改 auth、socketId、ownerId、成员表或部署配置。写入以 Redis CAS 保留并发变更，并在同一事务核验会话、join 状态和撤销标记。
- `POST / PUT / DELETE /api/v1/native/records`：分别列表、下载链接、删除。每次按已确认 joinId 解析 Space；拒绝兄弟 Space、嵌套文件/私密 Room 路径。外部服务失败返回统一错误，不回传存储端点凭证。
- Native Bearer 继续无法调用 legacy 管理入口。Web 身份与 UI 均保留原路径。

创建者凭据 `v1:native-owner:<session-id>:<space>` 与个人偏好 `v1:native-preferences:<session-id>:<space>` 的 TTL 不超过当前匿名会话。它们不是长期用户账号；退出会议可恢复，匿名凭证过期/清除后不能凭昵称认领原所有权。后续外部用户体系应提供稳定主体绑定与迁移。

客户端设置请求绑定当前房间生命周期；保存失败保留草稿，迟到读取不能覆盖刚保存的结果，退出会取消请求。房主滑走需确认，继续复用现有会议控制器和先退出再加入的流程。

## 仍属于独立能力的事项

- Native AVO 动画、文件导入导出、视频虚化、虚拟角色/背景和屏幕共享音频尚未实现；当前是偏好数据接入，不能作为媒体效果验收。
- AI 部署密钥、证书更新/订阅与部署仪表盘属于部署管理员或平台身份能力，匿名房主不拥有这些权限。沿用 Web 匿名用户的 AI 隐藏规则；商业化仍后置。
- 私密 Room 入会、Native 成员管理/主持操作完整菜单、录制开始/停止等不由设置数据接口代替；本批录制范围为历史文件列表/下载/删除。
- 既有容量预留、进程被杀后的媒体补偿和外部账号集成仍以 checklist 未完成项为准。

## 回归方式

1. 更新源码后重启 API 与 Metro：`pnpm dev:api`、`pnpm dev:mobile`；本批未新增原生依赖，无需仅因这些修改重建 development build。
2. 首页输入一个新 Space，确认成功入会、两个公共 Room、创建者可主动开启设备；Web 可发现并加入该 Space。另一个 App 会话使用相同昵称不能取得房主权限。
3. 对比 Web 的成员数据与 App 设置：修改名称、状态、AVO、音频偏好及房间配置，退出/重入检查恢复；访客不能保存房主字段。输入草稿在 API 失败时保留。
4. 设置访客策略后验证访问限制；离开和重入、滑动、后台、取消均检查媒体清理与房主确认。
5. 用测试录制文件验证真实 S3 列表、下载和删除确认；用 iPhone/Android 真机验证麦克风参数、音量与摄像头/共享采集。不要使用唯一一份生产录制做删除回归。
