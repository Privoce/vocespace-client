# Mobile / Web Phone 工具与文件对齐（2026-11-16）

## 修复范围与原因

- 工具清单：旧 Web 主会场写在 `uploads/<space>/<space>`，Native 写在 `uploads/<space>`。两个适配器现在共用目录解析，主会场统一到后者，子房间目录不变。首次访问合并两份清单，按 ID 去重，复制旧图片并保留旧 URL 可读；旧清单重命名为 `.migrated`，不会重复合并。
- 白板：当前房间已有白板时返回已有记录，不再因重复创建报错。Native 从只有图标/弹窗改为 Tile 内的真实白板，切换全屏保持同一实例。共用 contracts 解析 Web 的 HSL 颜色、归一化点和笔宽，Native SVG 与 Web 使用相同的 `0 0 1 1` 坐标系。原 Native 只收 hex、API 强制笔宽 3 的做法会导致两端笔迹不一致。
- 工具：Native 图片、iframe、Cobrowse、白板在 Tile 内呈现，并显示全屏与自己的 Tile 的关闭按钮。删除仍经确认成员和原服务端 owner 校验。Cobrowse WebView 使用与 Web 同版本的 Hyperbeam SDK（固定 `0.0.38` 的 unpkg 模块），不是只导航到 embed URL；保持 WebView 挂载，销毁时清理 SDK。
- Web Phone 全屏：工具操作改为控制 PhoneMeeting 的 `fullscreenTileId`，不再只修改桌面 store；触屏设备始终显示工具按钮，额外 Tile 使用完整舞台高度。
- 聊天附件：保留原文件名和存储名，图片从成员限定、短期有效的 URL 加载缩略图，点击全屏查看；普通文件点击获取 attachment 下载链接交给系统处理。历史消息若已丢失附件标识仍保留文件列表入口，无法凭空恢复原附件。
- 会议文件：按参考图改为居中深色弹窗、两列图片/文件图标网格，显示原文件名；API 保留旧 `files` 字段并增加名字映射。图库与全屏图片共用一个 Native Modal，避免叠加层级问题。缩略图能力定期续取，离开时停止请求。
- 屏幕共享：Web 的 PC、Phone、共享 Phone 和入会后授权开启入口均显式使用 VP8 发布屏幕，避免默认 VP9 的端间兼容差异；摄像头编码配置不变。Native 在屏幕 publication 出现时挂载视频视图，按 track SID 区分重新发布的轨道，并在重连后恢复当前公开房间订阅。未获得故障当时的 RTC 日志，不能把编码认定为真机问题唯一原因。
