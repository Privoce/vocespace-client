# Mobile / Web Phone 会议调整（2026-11-03）

## 广场与预览来源

广场的 `GET /api/v1/native/spaces` 原先只读取 Redis `space:list:` 索引及 `space:<name>` 业务数据，把持久化参与者数当作在线人数。业务配置可以在 LiveKit 房间结束后继续存在，因此列表中的历史 Space 不代表当前运行中的会议。这不是客户端生成的演示列表。

2026-11-04 按用户纠正明确候选来源：先调用 LiveKit `listRooms()`，再按返回的房间名读取 Redis `space:<name>`，核对公开策略和业务数据；不再遍历或依赖 Redis `space:list:` 索引。索引缺失、历史坏记录均不应影响有效活跃房间的发现。Space 的公开策略使用 `allowGuest === 'allow'`，取消房主查看自己非公开 Space 的广场例外；子 Room 的私密性使用 `isPrivate`。

没有媒体房间、无人会议、仅预览机器人或未登记媒体成员的房间不进入广场；人数只统计实际连接的业务成员。读取不删除历史配置、聊天或账号房间数据。房间在查询途中消失按空房处理，媒体服务故障仍报错，不回退展示 Redis 历史记录。

预览快照同样核对真实连接，仅保留主会场成员，排除公共/私密子房间、隐藏媒体客户端和离线记录。不存在的房间不会因旧成员记录启动 Egress；预览源退出后快照失效。原 HLS 租约、权限校验和发布授权不变。

目录展示和 HLS 就绪是两个状态：用户停留预览卡片后请求预览接口，由现有 Egress 任务生成切片，经媒体网关提供 HLS。LiveKit 存在房间不代表 HLS 已自动生成，真实输出仍需 Egress/存储/播放链路回归。

“我的”列表来自账号房间记录，并保留用户名房间入口；这些是可进入/创建的入口，不是正在直播的证明。本次不改账号房间归属或删除记录。

## 共享会议界面

- Mobile / Web Phone 底部 Dock 只显示 Chat，展开按钮直接打开聊天。成员查看与管理仍通过头部/更多入口访问。
- 移除可见分页器，保留现有横向滑动翻页逻辑。
- 共享底栏与旧 Web Phone 底栏使用 flex `space-between`，按钮不再等分拉伸。
- tile 的 focus 操作始终显示 focus 图标；再次点击仍取消聚焦，无障碍操作名称保留状态语义。
