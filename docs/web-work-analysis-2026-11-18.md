## 模型额度错误处理

用户提供的日志显示 DashScope 返回 `403 / AllocationQuota.FreeTierOnly`，表示免费额度已耗尽且开启仅免费额度模式。这是模型服务的额度限制，当前网页的通用 500 隐藏了原因。

- API 将该已知错误映射为 `503 / AI_QUOTA_EXHAUSTED`；仅返回固定的公开提示，不透传供应商请求头、原始错误或密钥。
- Web 中英俄提示额度原因并停止分析；其他请求错误不再误提示屏幕共享权限不足。
- 模型请求失败后停止服务时不再发起最终总结；空会话同样跳过总结，正常会话保留原有总结流程。
- 本地模拟验证新增 4 项：错误映射与脱敏、空会话停止、已有记录后额度失败不再请求、正常会话总结。与采集 5 项合计 9 项通过；全项目及 API 类型检查通过。
- 供应商控制台设置尚未更改，未重放用户附带的真实截图请求。真实调用恢复需要管理员处理额度或计费设置。

## 配置刷新与 Responses 协议

进一步确认 AI 路由原本在模块加载时用 `const { ai } = getConfig()` 保存快照，用户服务缓存也持有旧 SDK 客户端；因此更新为火山配置后仍可访问旧阿里云服务。此前的免费额度错误仅描述旧请求，不能判断新供应商账户的额度。

- 每次 GET/POST 读取当前 AI 配置，禁用即时生效；已缓存服务在密钥、地址、模型或输出上限变化时更新客户端，并保留分析记录。
- URL 以 `/responses` 结尾时使用 Responses API，转换屏幕图片/文本输入并提取输出文本；以 `/chat/completions` 结尾或基础 URL 时使用 Chat API，避免重复拼接路径。
- `maxTokens` 分别传递为 `max_output_tokens` / `max_tokens`。不完整或空文本响应按失败处理。
- 通过本地模拟供应商验证相同会话的协议/密钥切换、实际请求 URL、图片输入、120000 输出上限、历史保留及禁用。合计 10 项相关测试通过；API 类型检查通过。未调用用户真实模型，也未验证账户额度。
- API 代码修复需要重启服务加载新制品；修复后继续更新 AI 配置无需为此重启。
