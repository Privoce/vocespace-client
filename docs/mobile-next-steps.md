## 主线批次与通过条件

### A：核心会议短回归与界面收尾（4.4）

目标：建立后续滑动切换可以复用的稳定会议基础，不以高级设置全部可用为前提。

- 对照 Web Phone 检查会议卡片、控制栏、聊天/成员、设置返回、长昵称、中文键盘及三语；保留 Web PC/Phone 已确认外观。
- 检查手动加入/退出、重复点击、Web 邀请上麦与撤销、媒体开启时退出确认、切 Tab/后台清理和断线重连。
- 明确缺陷与未实现能力，修复阻断入房、退出、媒体释放的问题；不在本批扩大角色权限或接通设置写入。
- 通过条件：不会残留旧房连接、重复加入、自动采集；界面回归与设备回归分别记录。Android 环境不足时保持未验收，不记作通过。

### B：滑动预览小范围验证（4.5 L0/L1）

目标：先证明真实预览可用，再扩大为发现流。延续 `app_直播.md` 的 HLS 优先验证路线，未通过 POC 前不承诺具体性能。

- 冻结首版交互：首页提供发现入口；会议 Tab 承载纵向全屏 Space 浏览/会中状态。消息/我的继续入口与本机设置。
- 用少量明确授权的测试 Space 验证 RN 播放器和独立预览源；确认当前 LiveKit/Egress/SDK 组合及媒体地址、存储、网关条件。
- 默认静音；记录首帧、直播延迟、缓冲、资源占用和切换释放。POC 阶段先手动加入，暂不启用自动加入。
- 验证预览不创建正式观众成员、不读私密聊天、不混入未授权轨道。
- 通过条件：真实流和授权隔离可演示，测量结果足以确定体验阈值。若 HLS 不达标，再比较独立 preview RTC 中继；封面仅为降级。

### C：公开发现与上下滑动（4.5 L2/L3）

- 实现最小 feed DTO、分页、空态、关闭/失效房间及错误重试；旧 Space 默认不公开，不能因允许访客就进入发现列表。
- 提供主持人显式公开与选定轨道的配置入口；遵循原 Web 样式，将新增入口作为独立功能处理。
- 落地 worker 预览出口、唯一任务和重启恢复、预览租约与撤销，覆盖播放列表/片段等媒体请求授权。
- 纵向分页只保留一个活动播放器；邻页仅预取元数据/封面；快速滑动、取消请求、切 Tab/后台释放有明确所有者。
- 通过条件：A→B→C 快滑无旧画面回写、无双预览声音、无私密媒体泄露；仍允许手动加入。

### D：10 秒延迟加入与正式会议交接（4.5 L4/L5）

- 复用已有准备/确认/取消、墓碑、single-flight 和退出控制器；盘点现有 Native 试运行协议与目标 join-intent 的差异，再补容量预留与公开发现授权，避免复制第二套连接管理。
- 默认卡片至少 90% 可见、稳定 300ms 激活；连续 10 秒且有效播放至少 5 秒才自动加入，可关闭自动加入。
- 拖动、弹层、后台取消倒计时；首帧超时/长缓冲时取消本轮自动加入。最后一刻复核房间、代次、权限和容量。
- 正式 RTC 发声前停止预览；失败保留明确重试/手动加入路径。
- 普通观众滑走先退出旧正式会话；发布媒体等高风险状态先确认，取消则保留旧会议。首版仍不新增 Native 主持/共享屏幕/录制管理能力。
- 通过条件：9.9/10 秒边界、取消与确认竞态、重复点击/回调、失败补偿均通过；始终至多一个正式会议。

### E：稳定性、独立部署与综合验收（4.5 L6 → 4.6 → 4.7）

- 完成权限撤销、资源降级、持续切换及真实媒体验证；按 POC 定稿的阈值记录性能，不提前编造通过指标。
- 交付 Web/API 独立镜像、Compose、环境示例、健康检查、持久化与媒体依赖说明；基于实际制品编写安装手册及安装 SKILL。
- 验证全新安装、重启、备份恢复与升级回退，再执行 Web PC/Phone 与 App 双端真机综合回归。
- 通过条件：首版会议直播闭环可以按文档独立部署和复现；遗留限制明确，不将 JS 导出等同原生或真机验收。

## 设置功能独立批次（暂缓，不阻塞发现流）

恢复时建议按以下顺序，每批独立验收：

1. **真实读取与状态区分**：定位当前失败，核对 API 版本/路径、会话/成员和响应契约；兼容历史数据但不放宽授权。区分加载、未接通、无权限、服务失败与平台不支持，错误详情用于诊断，不向用户暴露密钥。
2. **自身可写偏好**：逐项定义服务端授权及保存/失败/重试语义；昵称、状态、提示音和 AVO 预设等不能默认沿用 Web 管理权限。设备音量/处理等须分清本机效果与服务端存储。
3. **Native 媒体能力**：按真机支持程度实现设备选择、音频路由、前后摄像头、AVO 动画、虚拟背景/角色；布局复用不保证原 Web 媒体实现能在 RN 运行。
4. **管理与外部服务能力**：AI、录制、证书/订阅在身份与授权方案明确后再接入；不因目录已有入口而默认向访客开放。

Umami、外部用户体系、私信和商业化继续后置。外部用户服务接入需保留主体映射边界，但不建设本地注册/密码体系来阻塞当前访客闭环。
