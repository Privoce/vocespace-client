# Mobile 白板、设备反馈与 HLS 启播（2026-11-17）

## 本次问题与处理

用户确认复现设备按钮无反应的是 Android 加入其他房主的房间，自己的房间可用。

- 原设备按钮在 Native 发布源权限或邀请列表为空时直接禁用。现在已连接时允许点击，由现有服务端设备授权接口重验；未获邀请仍拒绝采集，通过 Toast 和原有提示区解释原因。请求期间控制栏显示加载状态，继续防止重复采集。没有将房主权限授予访客。
- Native 白板原来只有画布。新增可收起、横向滚动的工具栏：画笔、擦除自己的笔迹、撤销/恢复、清空自己的墨迹、笔触大小和颜色。画布手势与工具栏分离，绘制期间暂停外层跨 Space 手势。同步按顺序发送快照，避免慢请求覆盖后发的撤销/清空。
- 工具网格中图标和文字成为一个完整点击区域。已有白板直接展开，不再再次请求创建；创建时保留可见的加载状态，失败给出提示。另一个 Room 已占用 Space 的唯一白板时显示对应限制，而非通用失败提示。白板接口本身只要求已确认成员，不因参与者不是房主而禁止创建或绘画；本次未改变服务端权限策略。

## 预览目标

5 秒指尽快显示 HLS 首帧的优化目标，不是硬超时，也没有修改现有的自动入会倒计时。

- Expo Video：前向缓冲 5 秒，Android 启播/缓冲恢复门槛 1 秒，iOS 关闭自动延长等待以避免卡顿的策略。
- 预览启动中的检查间隔从 2.5 秒缩短为 1 秒；暂不可用时从 10 秒缩短为 5 秒。离开页面仍取消请求并释放迟到的租约，不提前连接正式 RTC。
- 新 Egress 源使用 1 秒 HLS 切片及 1 秒关键帧间隔。字段单位依据 [LiveKit Egress API](https://docs.livekit.io/reference/other/egress/api/)。新设置需要更新 API 后，由新启动的预览任务使用；不强制终止现有任务。
- Egress 冷启动、对象存储上传和手机网络仍可能令首帧超过 5 秒。更短切片增加对象存储与媒体网关请求频率，低缓冲在弱网下更容易短暂卡顿，需真机实测取舍。
