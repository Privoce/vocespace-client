# Dashboard 鉴权、SMTP 与统计排查（2026-11-04）

## 问题与改动

用户明确要求 Dashboard 刷新无需管理员令牌。此前将刷新失败接到“配置全局画质”验证弹窗是错误的交互，本次已移除。

Dashboard 首次加载、手动刷新及定时刷新统一调用无需凭据的 `GET /api/space?dashboard=true`。服务端只投影表格需要的成员显示字段、布尔状态和使用时间，不返回完整 Space 配置、Socket 标识、媒体地址或密钥；现有详细管理接口与写入权限继续要求管理员验证。公共接口仅放行 GET 及单一 dashboard 参数，不能用混合管理参数绕过授权。

管理员凭据仍仅用于显式配置/管理操作。关闭弹窗保留验证，显式退出清除凭据。浏览器拒绝存储写入时，在当前页面内存中保留凭据；服务端始终负责最终授权。

SMTP 用户和发件人为空，是因为匿名 `/api/conf` 不包含 SMTP，而原先验证成功只更新了 UI 状态，没有重新读取完整配置。现在验证及打开缓存凭据对应的配置弹窗时，先重新验证并读取受保护配置，再显示表单。过期的异步配置响应不能覆盖更新的配置或撤销较新的验证。显式携带错误管理员凭据的 `/api/conf` 返回 403，匿名读取仍保留公开投影。
