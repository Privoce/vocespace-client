# Mobile 工具、聊天图片及屏幕共享排查

用户报告 Android 选择共享 App 后，系统仍显示共享提示但会议断开；接收其他人的屏幕共享无法播放，摄像头正常；工具不能创建 tile，聊天图片只进入会议文件列表。iOS 本轮尚未测试。

## 已确认并修复

- 当前 RN 0.83 从 `abort-controller` 安装全局 AbortSignal，该实现没有静态 `any` 方法。本机从 RN 依赖解析实际模块确认结果为 undefined。NativeRoom 的工具与 widgets 请求原先无条件调用该方法，可能在发 HTTP 前抛错。改为监听多个 signal 的兼容实现，请求结束解除监听，保留退出会议与组件卸载的取消语义。
- 工具列表轮询增加修订号，避免创建成功后被之前发出的旧列表覆盖。主动创建失败通过 Toast 提示，保持 tile 内不显示错误的原要求。
- 聊天契约原先丢弃全部 file 数据，Mobile 文件消息的按钮固定打开文件列表。现在只保留显示名称、类型和安全的存储文件名，不传旧附件 URL 或凭证；消息点击时通过已确认成员 API 获取短期链接。
- 图片在 App 内使用 Image 预览，不再跳外部浏览器；会议文件列表点击图片使用同一预览。服务端对聊天图片返回正确 image Content-Type 和 inline 响应，仍逐次检查会话/成员、文件路径和链接过期。旧无附件元数据的消息保留文件列表回退。

## 屏幕共享状态

保留当前工作区已有系统弹窗保护与后台策略改动；补充后台判定直接查询 LiveKit 实时屏幕发布状态，覆盖快照尚未同步的切后台时序。已测试系统选择器仍未结束、媒体更新、共享持续、取消以及广播停止后的清理规则。

未连接 Android 真机，无法采集该手机开始共享后的 RTC / MediaProjection 日志，不能将上述时序修正视为本次断联根因已被证实。接收他人屏幕共享的问题也未复现，订阅、编解码、服务器轨道权限和实际设备日志仍需继续核实；没有盲目更换编解码器或取消房间订阅隔离。

## 验证与交付

- 全量 51 文件 / 191 项测试通过，包含共享生命周期、取消传播、工具、聊天附件元数据、图片 inline 与权限撤销回归。
- 根、Mobile、API 类型、依赖边界、API 构建、部署初始化和差异空白检查通过。
- 本次没有生成新的 APK/IPA、部署 API 或执行真机验收。新包必须包含本次 JS 修改；图片响应及历史消息元数据需要配套 API 更新。本次没有新增原生依赖。
- 真机下一轮应区分：选择共享目标后立即返回 App 是否仍在会、停留目标 App 是否持续发布、远端实际能否收到屏幕轨道，以及本机接收他人共享时是否订阅成功但无法解码。系统共享常驻提示不能证明 RTC 房间仍在线。
